# 新疆腾讯街景导入（隐藏 / 常规分开）

网页版本: `v1.0.18`（2026-10-25）

## 源文件

`export (4) (1).json`（导出名「一个相对完整的新疆」），共 25,897 条，按 `source` 字段拆成三家：

| source | 条数 | 去重后 | 处理 |
|---|---|---|---|
| `qq_pano` | 12,874 | 12,845 | 移动性审计后拆成隐藏 / 常规两个集合 |
| `baidu_pano` | 13,022 | 12,986 | 暂存 `staging/baidu-xinjiang-20261025/`，未发布 |
| `google_pano` | 1 | 1 | 丢弃：坐标 37.62E / 55.75N 在莫斯科，与新疆无关 |

## 腾讯：先审计，再分流

对 12,845 个 `svid` 逐条请求腾讯元数据接口，按 `navigation-v1`（`tools/pano-mobility.js`）判定可移动性：

| 判定 | 条数 | 去向 |
|---|---|---|
| 隐藏（不可移动） | **7,170** | 「腾讯隐藏街景/时光机」合集 |
| 常规（可移动） | **5,675** | 新建集合 `qq_xj`「腾讯常规街景·新疆导出」 |
| 无效 / 报错 | 0 | — |

去重规则：

- 7,170 条隐藏点里 1 条已在原合集中 → 实际新增 **7,169**。
- 5,675 条常规点里 **276** 条已存在于新疆城市图层（`data_65xxxx.js`）→ 不重复上传，实际新增 **5,399**。

> 用户要求：**常规和隐藏分开上传，不丢弃常规街景**。因此常规点单独成一个集合，
> 既不会混进「隐藏/时光机」，也不会被塞进按 adcode 组织的城市数据里（新疆只有乌鲁木齐、吐鲁番有完整区县边界，无法可靠归市）。

## 校验

- 审计覆盖 12,845 / 12,845，`invalid` 与 `error` 均为 0。
- 审计证据写回 `tools/data/hidden-collection-verification.json`：2,044 → **14,889** 条，
  后续导入 / 清理沿用同一份基线。
- 隐藏合集复用 `tools/merge_gap_scan.py` 的门禁（`can_import_record` 必须有 `status=hidden && canMove=false && movementCount=0`）。
- 常规集合按 18 万点/片约定写入 `data_qq_xj.js`（5,399 条，1 片），元数据 `name=腾讯常规街景·新疆导出`、`province=新疆维吾尔自治区`。
- `grid_all.js`、`pano_search_index.js`、隐藏网格由 `tools/build_viewer_index.js` 全量重建。

## 备注

- 常规集合使用 `腾讯导出` 作为来源标记，便于与扫描数据（`soso`、`g312` 等）区分。
- 该集合的点位目前不参与区县筛选（新疆缺区县边界数据），只按集合展示。
