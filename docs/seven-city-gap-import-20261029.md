## 2. 移动性审计

工具：`tools/audit_gap_scan_mobility.mjs`，判定规则沿用 `tools/pano-mobility.js` 的 `navigation-v1`：
实时请求 `https://sv.map.qq.com/sv?svid=<id>&output=json`，只有 `roads[].points` 前后相邻帧、
`vpoints[].link`、`all_scenes` 相邻位才算「可移动」。自引用、邻接 `0,0`、坐标非法、元数据报错、`svid` 不匹配都不算。

并新增 `batches` 字段记录本批的来源与计数。

> 审计过程遇到 `/sv` 网关限流。服务端配额是 **16.7 点/秒（约 1,000 次/分钟）**，超过后同一出口
> 会收到 `500`（`Cost: 0`，网关侧拒绝）并持续一段时间。本次实测直连以 24 点/秒跑到约 1,600 次即被拒。
> 处理方式：脚本改为令牌桶限速（起步 8 点/秒，成功后逐步上调、上限 16.7 点/秒，被拒则降到 0.6 倍并冷却），
> 期间再与本地 HTTP 代理交替分流，两个出口各承担一半请求。判定结果与出口无关，不影响证据有效性。

## 3. 分流规则

| 审计结论 | 去向 | 标记 |
|---|---|---|
| 隐藏（不可移动） | `hidden_<地级码>` | `腾讯隐藏` |
| 常规（可移动） | `qq_<省码>` | `腾讯常规` |
| 已在城市图层 / 已在集合里 | 跳过 | — |

行政区归属用 DataV GeoAtlas 地级边界做点在面内判定（GCJ-02，与街景坐标同基准），
落在所有多边形外时按最近边界（≤120 km）归属；本批 0 条落空。

## 6. 已知边界（诚实说明）

- 审计依赖腾讯元数据的邻接关系，属**服务端视角的可移动性**；元数据缺邻接、客户端实际可移动的极端情况识别不了。
- 本批只核验了这 9,114 条候选；合集里其余历史点位没有重新核验（基线里 82,434 条是累计已核验的部分）。
- 候选的 `isHidden` 标注与审计结论在本批里没有冲突到需要人工仲裁的情形（未出现 `invalid`），
  但这只说明这批数据的元数据都正常返回，不代表扫描器的标注可信。
- 限流是外部服务的临时行为，失败记录会以 `error` 落盘并在续跑时重试；本次最终 `error = 0`。
