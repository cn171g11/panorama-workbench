# 海南补扫：首轮漏采 85%

网页版本: `v2.5.0`（2026-10-31）

## 1. 问题

`v2.4.0` 的海南 117,553 点（海口 41,237 / 三亚 38,295 / 儋州 5,162 / 省直辖 33,293）看着完整，
但用桌面上的官方扫描器「街景扫描器 v1.1」交叉验证后，结论是**成段缺失**。

| 对比 | 数值 |
|---|---|
| 官方扫描器结果 | 441,639 |
| 其中我方没有的 | **375,609（85.1%）** |
| 我方独有（官方未走到） | 51,523 |
| 并集 | **493,162** |

抽样看缺口：随机取 5 个"官方有、我方无"的点，最近的我方点位在 170–881 m 之外——
不是坐标错位，是整段路没被扫到。

## 2. 根因：播种半径小于网格间距

| | 首轮（我） | 官方 |
|---|---|---|
| 网格间距 | 0.01°（约 1.1 km） | 1.5 km |
| 探测半径 `r` | **250 m** | **1500 m** |
| 半对角线 | 778 m | 1,061 m |
| 覆盖保证 | **无**（250 < 778，网格之间留空洞） | 有（1500 > 1061） |

`/xf` 每个探测点只返回**一个**最近的 pano。半径小于半对角线时，落在两条探测线中间的路
永远不会被播到种子，后续 BFS 也就无从发现。首轮 31,924 个探测点里有大量落在"最近的 pano 已在 250 m 外"的空档上。

修复：`tools/scan_boundary_streetview.mjs` 新增 `--radius`，并在半径小于半对角线时打印
`WARN radius ... roads between probes will be missed`，避免再犯。

## 3. 重扫

用官方扫描器本体跑，同时做了一处必要调整：

> 它原生把省拆成 18 个市县逐个扫，而每个市县的 BFS 不按边界裁剪队列，会顺着 `all_scenes`
> 把整岛走一遍——18 个市等于走 18 遍。改成用省界一次遍历（`run_island.py`），算法与覆盖不变。

| 项 | 值 |
|---|---|
| 播种 | 17,584 个探测点（1.5 km 网格，`r=1500`） |
| 采集 | **441,639 点** |
| 耗时 | 26,848 秒（7.5 小时），16.4 点/秒，**0 错误** |
| 出口 | 直连被封后切代理，全程未中断 |

三沙（460300）依旧不参与：边界跨 8°×14°，且实测永兴岛/西沙/南沙无街景。

## 5. 官方数据自身的缺口（必须说明）

官方扫描器的点位经度范围是 **109.822–110.973 E**，而海南岛西起 108.59 E：

- 东方、昌江、乐东西部、儋州西侧基本没有它的点；
- 三亚城区（18.19–18.35 N）它的点也很少，`460200` 的增量是 0。

原因是它的播种同样受"最近 pano"影响：西部/南部覆盖稀疏时，1.5 km 网格里大量探测点返回同一个远处 pano。
所以并集里 51,523 个"我方独有"的点恰好补上了这些区域——**两套合起来才接近完整**，任何一套单独都不够。

## 6. 结果

| 项 | 前 | 后 |
|---|---|---|
| 街景点总数 | 22,162,782 | **22,538,104** |
| 海南省 | 117,987 | **493,309** |
| 数据分片 | 427 | **428** |
| 网格单元 | 466,753 | **469,482** |

校验：`check_viewer_hidden_grid`（137 集 / 102,067 点）通过；`check_viewer_display_mode` PASS；
`entries=22,538,104` 与 `PANO_COUNT` 相等；并集 493,162 个 sid 在 `data_46*.js` 中**各出现 1 次**（缺失 0、重复 0）。

## 7. 教训

1. **播种半径必须 ≥ 网格半对角线**（间隔 s 时 r ≥ s/√2），否则覆盖有洞——首轮就是 250 m 配 1.1 km。
2. **"扫完了"不等于"扫全了"**：首轮 frontier 归零、0 错误、校验全绿，但只覆盖了 15%。
   验收标准应该是**与另一套独立结果比对**，而不是只看自己的指标。
3. 官方工具有它自己的偏差（西部/南部缺失），照样不能盲信——交叉验证 + 并集才是稳妥做法。
